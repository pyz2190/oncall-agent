# 网络分区告警处理方案

## 告警名称
- **告警名**: `NetworkPartition`
- **告警级别**: 紧急
- **触发条件**: 节点间网络心跳连续丢失超过30秒，或跨可用区延迟持续超过500ms

## 问题描述
网络分区指集群中部分节点之间无法正常通信，是分布式系统中最危险的故障之一，可能导致：
- 集群脑裂（split-brain）
- 数据不一致或写入冲突
- 主从切换异常
- 服务注册与发现失效

## 排查步骤

### 步骤1: 获取当前时间
**工具**: `get_current_time`
**目的**: 锁定网络异常发生的时间窗口

### 步骤2: 查询网络监控日志
**工具**: `query_logs`
**参数要求**:
- **地域**: `ap-guangzhou`
- **日志主题**: `network-metrics`
- **时间范围**: 最近20分钟
- **查询条件**: `packet_loss OR latency OR heartbeat_timeout`

**查询示例**:
```
地域: ap-guangzhou
日志主题: network-metrics
时间范围: [当前时间-20分钟] 到 [当前时间]
查询语句: (packet_loss > 5 OR latency > 500) AND zone:*
```

### 步骤3: 查询集群协调日志
**工具**: `query_logs`
**参数要求**:
- **地域**: `ap-guangzhou`
- **日志主题**: `application-logs`
- **时间范围**: 与告警时间一致
- **查询条件**: `leader election OR split-brain OR node unreachable`

### 步骤4: 补充内部处理经验
**工具**: `query_internal_docs`
**目的**: 检索网络分区与脑裂的应急处理预案

## 常见原因分析

### 原因1: 物理网络故障
**特征**:
- 特定可用区或机架整体不可达
- 丢包率突增至较高水平
- 云厂商网络状态页有告警

**处理方案**:
1. 确认是否为云厂商网络故障
2. 将流量切换到健康可用区
3. 暂停跨区写入，避免数据冲突
4. 等待网络恢复后再校验数据一致性

### 原因2: 安全组/防火墙变更
**特征**:
- 故障紧随一次配置变更发生
- 部分端口连接被拒绝
- 仅特定服务间通信中断

**处理方案**:
1. 回溯最近的安全组/防火墙变更记录
2. 回滚错误的网络策略
3. 验证关键端口连通性
4. 建立变更评审流程

### 原因3: 节点负载过高导致心跳超时
**特征**:
- 节点CPU或网络带宽打满
- 心跳延迟但物理网络正常
- 伴随其他资源告警

**处理方案**:
1. 降低高负载节点压力或扩容
2. 适当调大心跳超时阈值
3. 隔离故障节点防止脑裂
4. 恢复后重新加入集群

## 紧急处理措施

### 立即操作（5分钟内）
1. **隔离**: 隔离不可达节点，防止脑裂写入
2. **切流**: 将流量切到健康可用区
3. **冻结**: 必要时冻结跨区写操作

### 短期措施（30分钟内）
1. 定位网络故障范围与根因
2. 协调云厂商或网络团队处理
3. 网络恢复后校验数据一致性

### 长期优化
1. 多可用区部署与容灾演练
2. 完善脑裂仲裁机制（quorum）
3. 网络变更纳入严格评审
4. 增加链路质量监控

## 验证步骤
1. 确认节点间心跳恢复正常
2. 确认丢包率与延迟回到正常区间
3. 校验集群无脑裂、数据一致
4. 观察30分钟确保链路稳定

## 相关告警
- `ServiceUnavailable`: 服务不可用
- `SlowResponse`: 响应时间过长
- `DatabaseConnectionPoolExhausted`: 数据库连接池耗尽
