# SSL/TLS证书过期告警处理方案

## 告警名称
- **告警名**: `CertificateExpired`
- **告警级别**: 严重
- **触发条件**: HTTPS证书有效期剩余不足7天，或已过期

## 问题描述
SSL/TLS证书过期会导致客户端无法建立安全连接，可能造成：
- 浏览器显示不安全警告，用户流失
- API调用方因证书校验失败而中断
- 移动端因证书锁定（pinning）直接报错
- 合规与安全风险

## 排查步骤

### 步骤1: 获取当前时间
**工具**: `get_current_time`
**目的**: 确认当前时间，计算证书剩余有效期

### 步骤2: 查询网关访问日志
**工具**: `query_logs`
**参数要求**:
- **地域**: `ap-guangzhou`
- **日志主题**: `gateway-logs`
- **时间范围**: 最近15分钟
- **查询条件**: `SSL handshake failed OR certificate expired OR TLS error`

**查询示例**:
```
地域: ap-guangzhou
日志主题: gateway-logs
时间范围: [当前时间-15分钟] 到 [当前时间]
查询语句: ("SSL handshake" OR "certificate") AND level:ERROR
```

### 步骤3: 查询客户端错误日志
**工具**: `query_logs`
**参数要求**:
- **地域**: `ap-guangzhou`
- **日志主题**: `application-logs`
- **时间范围**: 与告警时间一致
- **查询条件**: `PKIX OR certificate validation OR handshake`

### 步骤4: 补充内部处理经验
**工具**: `query_internal_docs`
**目的**: 检索证书更换与灰度发布的标准流程

## 常见原因分析

### 原因1: 证书到期未及时续期
**特征**:
- 证书 notAfter 时间已过或临近
- 所有走该证书的服务同时报错
- 无相关代码或配置变更

**处理方案**:
1. 立即签发或续期新证书
2. 在网关/负载均衡更新证书
3. 平滑重载配置，避免中断
4. 验证证书链完整

### 原因2: 证书链不完整
**特征**:
- 部分客户端报错，部分正常
- 缺少中间CA证书
- 浏览器可访问但API调用失败

**处理方案**:
1. 检查并补全中间证书链
2. 重新部署完整证书包
3. 用工具验证证书链
4. 通知调用方更新信任库（如需要）

### 原因3: 自动续期任务失败
**特征**:
- 自动化续期（如ACME）报错
- 证书未按计划更新
- 续期日志中有失败记录

**处理方案**:
1. 检查自动续期任务状态与日志
2. 修复续期失败原因（权限/域名校验）
3. 手动续期作为兜底
4. 增加续期失败告警

## 紧急处理措施

### 立即操作（5分钟内）
1. **续期**: 紧急签发并部署新证书
2. **重载**: 平滑重载网关配置生效
3. **公告**: 必要时通知受影响调用方

### 短期措施（30分钟内）
1. 确认所有节点证书已更新
2. 验证各端连接恢复正常
3. 排查自动续期失效根因

### 长期优化
1. 建立证书有效期集中台账
2. 配置提前30天到期告警
3. 完善自动续期与回滚机制
4. 定期演练证书轮换

## 验证步骤
1. 确认新证书生效且有效期充足
2. 确认HTTPS连接无安全警告
3. 确认API调用方握手成功
4. 观察15分钟无新的TLS错误

## 相关告警
- `ServiceUnavailable`: 服务不可用
- `SlowResponse`: 响应时间过长
