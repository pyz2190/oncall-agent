# 智能 OnCall Agent 项目说明

## 项目定位

智能 OnCall Agent 是一个面向值班工程师的 AIOps 辅助诊断系统。系统把告警读取、日志查询、知识库检索、智能体推理、诊断报告生成和人工审批交互整合到同一个 Web 工作台中，目标是在故障发生时降低排查成本，提高诊断过程的透明度和可交接性。

## 核心问题

传统 OnCall 排障通常存在三个痛点：

1. 告警、日志、文档分散在不同平台，工程师需要频繁切换工具。
2. AI 直接给结论时缺少推理过程、证据来源和人工确认机制。
3. 排查完成后还需要手工整理事故报告，影响交接效率。

本项目围绕这些问题设计了“可观察、可追溯、可确认、可导出”的智能诊断流程。

## 系统架构

项目采用前后端一体的 Spring Boot Web 应用：

- 前端：原生 HTML/CSS/JavaScript，实现聊天工作台、命令中心、右侧诊断面板、确认卡、时间线、报告图表和可访问性设置。
- 后端：Spring Boot 提供 REST 与 SSE 流式接口，负责任务编排、会话管理、工具注册、审批流和结构化报告输出。
- 大模型：通过 DashScope 调用 Qwen 系列模型，完成对话、推理和诊断报告生成。
- 知识库：Markdown 文档切分后写入 Milvus，支持内部文档检索与证据引用。
- 外部工具：通过腾讯云 CLS MCP Server 接入真实日志查询能力；Prometheus 当前保留 mock 指标/告警，方便课堂稳定演示。

## 已完成功能

### 1. 流式智能对话

用户输入问题后，后端通过 SSE 持续返回模型内容，前端实时渲染回复，避免长时间等待导致的黑盒感。

亮点：

- 支持多轮会话上下文。
- 支持后端结构化 `agent_step` 时间线。
- 普通聊天默认注册本地安全工具，降低外部工具 schema 对基础聊天的影响。

### 2. Agent 思考时间线

系统会展示智能体的关键步骤，包括构建上下文、注册工具、模型推理、工具执行、观察结果和最终输出。

HCI 价值：

- 增强系统可解释性。
- 降低用户等待焦虑。
- 让用户理解 AI 当前处于“思考、行动、观察、总结”的哪一阶段。

### 3. 语音输入

前端支持浏览器语音识别入口，用户可以通过语音输入排障问题，适合值班、夜间或不方便打字的场景。

演示提醒：

- 需要使用支持 Web Speech API 的浏览器。
- 首次使用时浏览器会请求麦克风权限。

### 4. 自动化档位与审批流

系统提供手动、确认、自动三种自动化档位：

- 手动：用户明确控制诊断动作。
- 确认：后端发起工具链执行前暂停，等待用户在确认卡中批准或拒绝。
- 自动：系统自动放行诊断工具链。

现在审批流已和后端打通：

- 后端通过 `action_required` SSE 事件创建待审批动作。
- 前端确认卡调用 `/api/actions/{actionId}/decision`。
- 后端根据审批结果继续执行或取消工具链。

### 5. AIOps 自动诊断

系统可以读取告警、调用工具、组织多 Agent 编排，并生成 Markdown 诊断报告。

报告内容包括：

- 活跃告警清单。
- 告警根因分析。
- 日志与指标证据。
- 排查步骤。
- 处理建议。
- 风险评估。

### 6. 结构化报告与图表

后端会从最终报告中生成 `report_data` 结构化数据，前端优先使用该结构渲染右侧卡片、告警表和统计图表。

改进点：

- 不再依赖前端默认假数据。
- 没有结构化数据时显示空状态。
- 图表和报告文本保持一致。

### 7. 知识库与证据溯源

系统支持上传 Markdown 知识库文档，写入 Milvus 后用于内部知识检索。

前端支持证据来源展示：

- Agent 回答引用知识库内容时，可以展示来源标记。
- 用户可以查看来源片段，增强可信度。

### 8. 反馈机制

每条 Agent 回复支持用户反馈，便于记录回答是否有帮助，以及标注推理问题。

HCI 价值：

- 体现人机协作闭环。
- 为后续优化 Agent 回答质量提供数据。

### 9. 事故报告导出

诊断完成后，用户可以把当前诊断过程整理为 Markdown 事故报告，用于值班交接、复盘或课堂演示。

### 10. 可访问性与可读性设置

系统支持深色模式、字号调节和高对比模式，适配夜间值班和不同阅读需求。

## 演示流程建议

1. 打开系统首页，展示整体工作台布局。
2. 在聊天框输入一个普通问题，展示流式回复和 Agent 时间线。
3. 切换主题、字号或高对比模式，说明可访问性设计。
4. 打开右侧 AIOps 面板，选择“确认”模式运行诊断，展示后端审批卡。
5. 拒绝一次审批，说明后端不会执行工具链。
6. 再选择“自动”模式运行诊断，展示告警报告、右侧结构化图表和告警表。
7. 展示知识库来源、反馈按钮和报告导出能力。
8. 说明腾讯云 CLS MCP 已接入，Prometheus 当前使用 mock 数据以保证课堂演示稳定。

## 技术亮点

- SSE 流式通信：模型回复、Agent 步骤、审批状态、报告数据都通过流式事件推送。
- 后端审批门控：自动化执行不只是前端按钮，而是后端真正暂停和等待决策。
- 结构化事件：`agent_step`、`action_required`、`action_status`、`report_data` 提升前后端契约清晰度。
- MCP 工具接入：通过本地 SSE MCP Server 接入腾讯云 CLS 日志能力。
- RAG 知识库：Markdown 文档进入 Milvus，支持知识检索和证据引用。
- HCI 设计：透明性、可追溯性、反馈闭环、可访问性和工作交接都映射到具体交互。

## 答辩可强调的 HCI 点

- 可见性：用户能看到 Agent 当前状态和执行阶段。
- 可控性：高风险工具执行前有确认卡，用户可以批准或拒绝。
- 可信度：回答和报告可以展示证据来源，减少黑盒结论。
- 可学习性：空状态、示例问题和清晰中文按钮降低上手成本。
- 可访问性：深色模式、字号、高对比适配夜间值班。
- 协作性：反馈机制和事故报告导出支持人与 AI 的工作交接。

## 当前演示环境说明

- 后端地址：`http://localhost:9900`
- 腾讯云 CLS MCP SSE：`http://localhost:3000/sse`
- Milvus：`localhost:19530`
- DashScope：需要有效 API Key，且账号不能欠费。
- Prometheus：当前为 mock 模式，便于稳定展示告警和指标。
